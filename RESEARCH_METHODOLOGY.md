# Research & Analysis Methodology

## Purpose

This document describes the methodology used in a curriculum-alignment research project.

The original project compared curriculum language with evidence from external English proficiency assessments. Because the source curriculum was proprietary, the public version describes the analytical process without reproducing the original curriculum data.

## Step 1 — Establish an Evidence Base

External assessment material was manually reviewed and language features were extracted into a structured database.

The database was organised by proficiency level and included observations relating to:

* Grammar
* Vocabulary
* Functional language
* Reading
* Listening
* Sentence structure
* Question formation
* Written and conversational language

The aim was to create an evidence base from actual assessment material rather than relying solely on general descriptions of proficiency levels.

## Step 2 — Build a Curriculum Dataset

Curriculum materials were manually reviewed and relevant language features were recorded.

Potentially significant items were categorised according to their linguistic function and potential learner difficulty.

This created a second dataset that could be compared with the assessment evidence.

## Step 3 — Compare Evidence

Each potential relationship was examined individually.

A simplified model was:

| Classification     | Meaning                                                                        |
| ------------------ | ------------------------------------------------------------------------------ |
| Direct             | Strong evidence of the same or substantially equivalent structure              |
| Related            | Linguistically related, but not sufficiently equivalent to call a direct match |
| Level/context      | Useful evidence of approximate difficulty, but not a direct structural match   |
| No direct evidence | The available assessment evidence does not establish a relationship            |

This distinction was used to avoid overstating the strength of a correlation.

## Step 4 — Examine Task Demands

The analysis did not treat grammar as an isolated variable.

For example, the following can represent progressively different learner demands:

```text
Recognise a structure
        ↓
Understand the structure in context
        ↓
Select the correct structure
        ↓
Manipulate the structure
        ↓
Produce the structure independently
        ↓
Use the structure in connected communication
```

Consequently, the presence of a grammar structure in a curriculum does not automatically demonstrate that learners are prepared to produce it independently.

## Step 5 — Identify Gaps

The comparison was used to identify areas such as:

* Language appearing in assessment evidence but receiving limited curriculum exposure
* Curriculum language without clear corresponding assessment evidence
* Receptive skills receiving more attention than productive skills
* Writing tasks requiring language that had not been sufficiently scaffolded
* Differences between individual grammar knowledge and connected-text demands
* Areas where additional teacher support could reduce learner difficulty

## Step 6 — Convert Findings into Documentation

The detailed evidence was consolidated into written analysis.

The documentation connected:

**Observation → Evidence → Interpretation → Curriculum implication**

This structure allowed individual findings to contribute to broader curriculum recommendations without losing the underlying evidence.

## Step 7 — Develop Practical Recommendations

The final stage translated analytical findings into practical curriculum-support proposals.

Examples of recommendation categories included:

* Visual language support
* Explicit grammar explanation
* Mnemonic strategies
* Guided production
* Writing scaffolds
* Teacher-ready activity mapping
* Clearer progression between levels
* More explicit identification of target language

## Confidentiality

The original project involved proprietary curriculum materials.

This public methodology intentionally omits:

* Curriculum titles
* Page numbers
* Proprietary examples
* Internal database identifiers
* Company-specific findings
* Internal documents

Any example data used in a public version should be synthetic or sufficiently generic that it cannot be used to reconstruct the original curriculum.

The objective of the public project is to demonstrate the **method**, not disclose the employer's intellectual property.
